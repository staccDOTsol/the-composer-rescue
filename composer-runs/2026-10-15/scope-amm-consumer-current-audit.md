Observed 2026-10-15 at confirmed mainnet slots 457351566–457352691. All transactions below used `simulateTransaction` on deployed programs with an actual serialized Solana v0/v1 message, `sigVerify:false` to model an existing payer/signer, and no `sendTransaction`. The source checkout is Kamino's `scope` commit `ce7c6d02a11968f7fce61517bce1bdffb533ca18`; source describes the mechanism, while the deployed binary decides the observed result. ## Deployed-binary ordering tests

The current Scope source's `refresh_price_list` checks the instructions sysvar and rejects any preceding instruction whose program ID is not Compute Budget, and rejects CPI refreshes. A swap or flash borrow must be a non-Compute-Budget instruction, so the needed sequence `swap/flash → Scope refresh → lender action` cannot update Scope from the already changed AMM pool in one transaction. The current binary confirmed this rule on **five distinct configured pool entries**: three Raydium CLMM entries, one from each AMM-bearing feed, and two Orca Whirlpool entries from different feeds. All five `refresh first` cases succeeded. The three Raydium `ComputeBudget → refresh` controls succeeded. All five `Memo → refresh` controls failed at Scope with custom error **6014 `RefreshWithUnexpectedIxs`**; the three wrong-pool controls failed **6004 `UnexpectedAccount`**. Wires were **350–480 bytes**, well below 4,096 bytes. See [`scope-live-ordering-replay.json`](scope-live-ordering-replay.json).

The exact CTALS consumer sequence was also tested. A two-entry Scope refresh of mapped Raydium pools 1 and 2 followed by `KLend.refresh_reserve` succeeded in a **498-byte** v1 message. Scope updated both entries' slots. KLend logged **`Price is too old age=187410 max_age=150`** for CTALS and set price status 61; its resulting reserve image and market price matched the `KLend.refresh_reserve`-only control. Reversing the order (`KLend → Scope`) failed 6014 at Scope, as did `Memo → Scope → KLend`. No borrow or withdrawal against the invalid CTALS price was accepted or claimed. See [`scope-ctals-klend-v1.json`](scope-ctals-klend-v1.json).

Finally, a real zero-fee KLend flash-loan instruction pair replayed successfully with zero change to the reserve supply vault, user token account, and fee vault. `Scope refresh → flash borrow → repay` also succeeded with the same three zero deltas in a **736-byte** v1 message. `Flash borrow → Scope refresh → repay` and `flash borrow → repay → Scope refresh` both failed 6014, with no committed post-account image. Thus a zero-fee flash loan cannot supply the pre-refresh AMM movement for this Scope route. See [`scope-klend-flash-ordering-v1.json`](scope-klend-flash-ordering-v1.json).

## Counts and limit

This pass ran **25 current-binary transaction simulations**: 16 producer ordering/binding tests, five CTALS consumer ordering tests, and four KLend flash ordering tests. It found **one directly configured KLend AMM-price consumer among 619 reserves**, but that reserve's price was stale and invalid in the successful refresh control. There is **no validated same-transaction outsider gain** through the tested Scope route. The ordering rule blocks a necessary step before a full swap/reverse/repay price-manipulation cycle, so no such completed cycle was represented as successful. A prepositioned AMM price from an earlier transaction, another oracle adapter, indirect Scope derived-entry chains, and unexamined consumers remain separate questions; this result does not certify all Solana AMM integrations safe.
